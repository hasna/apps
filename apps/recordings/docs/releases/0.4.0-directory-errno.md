# Directory enumeration error isolation

The native guard now clears `errno` immediately before every `readdir` call and
captures it only when that call returns `NULL`. Successful N-API array insertion
between reads can leave a nonzero `errno`; end-of-directory preserves that value.
Previously this could turn successful enumeration into a false recovery error.
No ownership, descriptor, deletion, signature, broker or platform guard changed.
The [POSIX readdir contract](https://pubs.opengroup.org/onlinepubs/007904875/functions/readdir_r.html)
requires distinguishing EOF from errors at the individual call boundary.

The aggregate Linux run `34130281545`, job `101768484051`, failed in the first,
deliberately reordered recovery control. Its retained artifact only contains the
subsequent missing legacy executable assertion. It does **not** retain the
recovery subprocess error or journal, so this defect is not proven to be that
failure's cause. The fixture now requires completed recovery, an absent journal,
and the deliberate refusal from the next archive verification before inspecting
the restored executable. Failure includes bounded subprocess stderr, journal
phase and app-presence metadata.

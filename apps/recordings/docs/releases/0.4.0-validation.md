# 0.4.0 release preparation

Status: draft; publication is blocked by the existing full release gate. This
record describes preparation and independent package checks, not a published
version or an accepted end-user application.

## Version and included source

The public registry reported `0.3.13` (published 2026-08-25) before preparation;
`0.4.0` was absent. The five pending Recordings Changesets include one minor and
four patches, so the next version is **0.4.0**. Only those Changesets were consumed.
The existing manual Unreleased S3 note was also moved into this release because
its source is already included. Other member versions are unchanged.

Included functionality spans the contracts credential/authority resolver, S3
audio artifacts, native recorder/history/settings/playback/paste improvements,
and the exported `RecordingsLib` provider API. This is not a native-library-only
release. Native consumers require Swift 6.2 and macOS 26.

## Independent checks

- Bun **1.3.14**: package typecheck and all three version sites pass at 0.4.0.
- Required affected build: **43 successful, 43 total**.
- Receipt regression suite: **10 pass, 0 fail, 20 assertions**. Controls reject
  ambient Git archive modes, changed source/package metadata, missing library/provider files, unsafe archive
  entries, wrong package identity, and registry metadata or byte mismatches.
- Actual macOS `npm pack` ran the native filesystem guard build, package build,
  version check, release scan, and artifact scan successfully. The archive has
  **274 files**, including **109 native package files**; no Python caches ship.
- Extracted archive: **26 Swift tests in 5 suites pass**, including live injected
  PCM ordering/pause/final WAV identity, cancellation, isolated preferences,
  service routing, and honest paste evidence. The three expected assertion
  integrity issues are deliberate negative controls, not ignored product errors.
- An external SwiftPM executable imports and links `RecordingsLib` from the
  extracted archive, including the public engine initializer and provider/session
  protocols. Its inert consumer runs successfully without starting capture.
- A separate npm project installed the archive and declared registry dependencies
  with lifecycle scripts disabled. TypeScript **5.9.3**, `strict: true`, and
  `skipLibCheck: false` checked the SDK consumer. Its loopback SDK request,
  explicit local CLI listing, and MCP stdio initialization/discovery/listing pass.
  All three binaries report 0.4.0. The installed serve binary returns version and
  health over loopback and refuses an unconfigured protected route with 503.

The first strict consumer attempt used TypeScript 5.8.2 with newly resolved Node
26 declarations and hit an upstream DOM TextEncoder/TextDecoder declaration
incompatibility; 5.9.3 checks the same declarations without suppressing errors.

## Publication boundary

Repair the failing paths and fixture isolation, rerun the strict full gate, and
review/merge the release changes before separately authorized publication.
Generate a fresh reviewed archive after any packaged-byte change. A prepared
receipt cannot authorize publication and cannot satisfy a released dependency.
After publishing the exact accepted archive, `native-core-receipt.py
--verify-registry` must match the registry metadata and downloaded bytes before
producing a separate `published` receipt. Consumers must pin that reviewed
receipt through trusted configuration. No npm publish, release tag, application
installation, or production provider acceptance is part of this preparation.

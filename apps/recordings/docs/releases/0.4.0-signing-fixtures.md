# Signing fixture repair

The initial macOS release gate had ten signed-build failures and three signing
manifest failures. The build fixtures used a fake Git executable and lacked a
committed source snapshot; real Darwin builds deliberately ignore that override.
The manifest fixtures placed fake signing tools on PATH, which the production
Darwin artifact CLI also deliberately ignores.

The repaired tests retain Darwin platform selection and the production build
flow. They create private canonical fixture roots, real Git trees/commit objects,
and archived source snapshots. Fixture commit objects retain the source commit's
identity metadata without overriding Git configuration or identity environment
variables. Tests copy the scripts and remap explicit tool/file capabilities only
inside those copies. The actual production scripts keep absolute tool pinning,
clean-source enforcement, and isolated-builder provenance checks.

Owned subprocess doubles model compilation, signing evidence, notary responses,
and package outputs. They do not invoke real signing, Keychain, installation, or
provider operations. File modes, source snapshots, signing evidence validation,
notary/archive digest comparisons, copied app tree comparisons, helper contracts,
and publication ordering still execute through the Darwin build flow. This is
fixture evidence, not a signed release, notarization, or installed-app acceptance.

Each child has an independent macOS sandbox: network access and unapproved
executables are denied, writes stay inside its fixture root, and legacy app,
preferences, Keychain, and TCC paths are excluded. Signal delivery is limited to
the same sandbox. A supervisor owns each build process group and enforces a
25-second child deadline. Negative controls cover real host-tool execution,
outside-root writes, legacy app reads, missing/dirty Git provenance, invalid
builder attestation, and an unexpected native export. Do not wrap these tests in
another sandbox; macOS refuses nested sandbox application.

The executing export-list regression also found a production integration defect:
`generate_and_verify_native_fs_guard` omitted `duplicateDirectoryDescriptor` and
the earlier `handleHasNoExtendedAcl` export. Both are now present in its sorted
expected list. Comparison remains exact; an added export still fails. The test
failed against the old list and passes against the corrected list.

Use Bun 1.3.14 and run only the owned groups:

```sh
bun test src/__tests__/macos-app-lifecycle.test.ts \
  src/__tests__/macos-artifact.test.ts \
  --test-name-pattern 'macOS signed artifact build|requirement.fixture|requirement-digest'
```

The existing twelve non-Darwin debug/local build cases retain their platform
skips; no failing signing test was skipped or allowlisted. Package typecheck and
strict typechecking of the new helpers pass. Attempting to strictly typecheck the
entire two legacy test files still reports preexisting errors also reproduced on
release revision `56f7b72fd`: artifact ZIP/identity types, installer assertions and
environment types, an older manifest fixture without `bundle_name`, and a readonly
parameterized journal test table. Those unrelated sections remain outside this
repair. A normalized comparison confirms the same nine diagnostics before and
after this change. The required affected build passes **43 of 43 tasks**. No broad
native release gate was run.

Measured focused result on Bun 1.3.14: **27 pass, 12 existing platform skips,
0 fail, 124 assertions** across the two groups. The separate supervisor deadline
and foreign-process control adds **1 pass, 0 fail, 6 assertions**. It verifies
that sandboxed signals cannot reach the foreign fixture process and that the
owned stalled process group terminates with the explicit deadline result.

The required repository `bun run check` also passes: package publication scans,
deployment lane checks, all **147 standard tests / 560 assertions**, and frozen
lockfile validation. This check does not execute the paused native release gate.

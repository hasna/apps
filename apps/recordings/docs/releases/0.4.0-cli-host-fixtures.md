# CLI, maintenance, Tailscale, and recorder fixture repair

The remaining CLI and Tailscale failures combined stale fixture assumptions with
real supported-host defects. This repair keeps the real Darwin branches and
production trust checks. No installed app, host signing tool, TCC database,
preference domain, or microphone is an input to the repaired fixtures.

## Production corrections

`resolve_tailscale_cli.sh` required `/usr/bin/realpath`, which is absent on the
supported Mac used for this validation. Canonicalization now uses Bash's physical
`cd -P` and `pwd -P` builtins in a subshell, with `CDPATH` cleared. The three callers
still reject leaf symlinks and require exact canonical-path equality. The owner,
mode, official Apple requirement, TeamIdentifier, bundle identifier, full-app
snapshot, and post-copy authentication checks are unchanged. A canonical owned
snapshot-parent test failed before this correction and passes afterward; hostile
PATH/CDPATH and symlinked leaf/ancestor controls also pass. The installer fixture
no longer substitutes the three obsolete realpath calls.

`app permissions` previously described a nonexistent canonical path as its
permission subject even when `installed` was false. It now passes an absent
subject explicitly. A confined empty-installation regression failed before the
one-line correction. With neither a bundle nor a stored TCC grant, the permission
state remains `not_determined`; a stored grant without a bundle is a separate
`unverified_no_installed_bundle` case.

## Fixture boundaries

- CLI status, permissions, and dependency reports run through the test-only
  `cli-app-fixture.ts` entry point under a per-child OS sandbox. Only exact
  read-only fictional codesign, defaults, process-list, and dependency responses
  are accepted. Nine other process entry points fail closed. System app discovery
  and TCC filesystem probes cannot consult host data. The compiled install fixture
  reaches the actual Darwin missing-envelope refusal, then independently checks
  interpreter validation; it does not expect a Linux-only platform error.
- Maintenance fixtures use the supported local-only installer path on Darwin.
  Copied-script tools model the approved machine identity and process evidence
  supplied by owned fixture reader leases. The real marker acquisition, reader
  drain, cleanup, and canonical owner/mode checks execute. Artifact authentication
  and fsync commands are explicit fixture boundaries here; this suite does not
  claim archive verification or crash durability. Verification deliberately exits
  79 after the drain, and tests require that it was reached. The release broker
  guard is unchanged. Darwin crash hooks remain disabled; their named boundaries
  prove ordinary marker cleanup, while the existing Linux crash/recovery test
  retains its platform skip on Darwin. Installer subprocess groups have a 15-second
  deadline and are killed only while their owned child is live.
- Tailscale fixtures use canonical private roots and copied absolute tool bindings
  under per-child OS confinement. The previously Linux-only positive full-app
  snapshot test now executes the actual Darwin path. Wrong team, wrong identifier,
  post-copy identity substitution, and unmapped real codesign all fail closed.
- Recorder tests default to refusing an unmocked capture process. Dependency
  availability and missing `rec` are explicit simulations. The dedicated runner
  `scripts/test-recorder-fixtures.ts` executes exactly `recorder.test.ts` with a
  process-denying preload and whole-process OS confinement on Darwin. Even direct
  execution of an installed `rec` binary is denied by the OS control. The runner
  also runs on Linux with the same simulated process boundaries, but Linux was
  not executed for this checkpoint. No recording acceptance is claimed.

Do not put an outer sandbox around the self-confined CLI, maintenance, Tailscale,
or recorder runner. Run recorder in its own group so Bun module mocks cannot
pollute other suites. The release gate must exclude `recorder.test.ts` from its
ordinary group, select it exactly once through the dedicated runner, and reconcile
its complete JUnit inventory. The test-only recorder runner and generated `dist/__tests__/` declarations are
explicitly excluded from the public package files while retaining development paths. It accepts only optional
`--junit-output /absolute/new/path`; the parent must be canonical, owned, and mode
0700. Export reads a nofollow regular source bounded to 32 MiB and creates the
new destination exclusively with nofollow and mode 0600. Existing paths,
symlinked/nonprivate parents, and overwrite attempts are rejected. Output streams
contain ordinary Bun test output; the report is Bun's JUnit XML. A live-child-only
30-second process-group deadline and final cleanup bound the runner.

## Validation on Bun 1.3.14 / macOS

```sh
bun test src/__tests__/cli.test.ts src/__tests__/install-maintenance.test.ts \
  src/__tests__/tailscale-cli-resolution.test.ts
bun scripts/test-recorder-fixtures.ts
bun test src/__tests__/recorder-fixture-runner.test.ts
bun run build:native-fs-guard
python3 src/__tests__/helpers/run-publication-fixtures.py --bun /absolute/pinned/bun
```

  439 assertions**. A final Tailscale-only rerun after tightening exact signing
  argument checks passes **25 tests / 82 assertions**.
- Dedicated recorder: **16 pass, 0 fail, 43 assertions**.
- Recorder report/inventory/refusal regressions: **3 pass, 0 fail, 13 assertions**.
- Confined installer/publication compatibility: **42 pass, 0 fail, 287 assertions**;
  93 existing platform/name-filter skips.
- Package typecheck and strict typechecking of the CLI, maintenance, Tailscale,
  recorder, runner regression tests, and new helpers/runner pass. The required
  affected build passes **43 of 43 tasks**.
- npm dry-run: **264 files**, all **9 declared bin/import/type targets** present;
  recorder runner and test helper implementations/declarations absent.
- Required repository `bun run check`: publication scans, deployment checks,
  **147 standard tests / 560 assertions**, and frozen lockfile validation pass.

The broad native release gate, real signing/notarization, application installation,

# Confined Darwin identity fixtures

This repairs the runtime-smoke identity and identity-migration fixture groups
listed in [the 0.4.0 validation baseline](0.4.0-validation.md). It is focused
fixture evidence, not a complete release gate or installed-app acceptance.

## Fixture isolation

The production scripts still determine Darwin with pinned `/usr/bin/uname`
and select pinned system tools. Tests copy those scripts into canonical,
user-owned mode-0700 scratch directories and bind explicit owned tool fixtures
after platform selection. Production scripts have no new override or bypass.
Native BSD ownership/path checks and the installer comparison-to-guard call
remain active. Signer, archive-verification, and process-list evidence are
fixture inputs; these tests do not claim to validate real signing or notarization.

Every Darwin child receives an OS sandbox. It denies network access, execution
outside an explicit allowlist, host application/Keychain/TCC/preference reads,
and persistent writes outside its scratch root. `/dev/null` and anonymous pipes
remain usable. Signals may target only processes in the same sandbox. A retained
supervisor starts and cleans up the fake app, wrapper, and preexisting fixture
process; the test runner no longer kills arbitrary PIDs read from files.
Child `HOME`, `TMPDIR`, working directory, and environment are isolated.

Negative controls verify denied real `open`, `defaults`, `codesign`, `security`,
and `tccutil` execution, absence of an attempted outside-write artifact, survival
of a separately owned process after a forbidden signal, and successful termination
of a child inside the sandbox. An unadapted smoke script ignores inherited test
tool overrides on actual Darwin and fails closed before launching any app.
Tool binding rejects missing/ambiguous insertion points, unsafe binding names,
symlinks, writable executables, and non-executable files.

Do not wrap these suites in another `sandbox-exec`: macOS rejects nested sandbox
application. Each fixture child establishes its own profile. Use Bun 1.3.14;
ensure child commands also resolve that pinned version.

## Updated obsolete expectations

Darwin shell release installation now always requires the root-owned updater
broker. The old tests expected a shell release request to reach signer comparison
and, with an approved identity pair, enter the installation transaction. Those
expectations are replaced with assertions that release requests refuse before
signing tools or a transaction, including approved and reversed identity pairs.
The broker and installer production checks are unchanged.

Direct execution of the sourced guard still checks its release decision table
and exact identity-pair approval. Darwin local-only fixtures execute the real
two-direction requirement comparison and guard: incompatible identities refuse,
the explicit ad-hoc approval permits progression, compatible identities need no
approval, and an unnecessary approval refuses. Non-Darwin fixture expectations
remain available for the historical test-override branch. Three existing
Darwin skips for non-Darwin preflight seams remain unchanged.

The smoke fixture retains the production readiness window of 100 attempts with
100ms polling. The first isolation fix shortened this to one second; subsequent
integrated and isolated reruns both timed out before malformed PID evidence was
published. A regression now delays the fake app launch by three seconds: it fails
with that shortened window and passes with the production window. The zero-delay
case remains covered. Completion and cleanup waits remain shortened for fixtures;
their assertions, including the exact malformed-evidence refusal, PID identity
changes, cooperative exit, verified TERM/KILL, and preservation of preexisting
processes are unchanged. No production timeout or script changed.

## Validation

From the package directory, with Bun 1.3.14:

```sh
bun test --timeout 120000 \
  src/__tests__/identity-migration-guard.test.ts \
  src/__tests__/macos-smoke-process-identity.test.ts
bun run typecheck
bun run build
bun x tsc --noEmit --strict --noUncheckedIndexedAccess --target ESNext \
  --module ESNext --moduleResolution bundler --types bun --skipLibCheck \
  src/__tests__/identity-migration-guard.test.ts \
  src/__tests__/macos-smoke-process-identity.test.ts
```

Focused result after the readiness follow-up: **55 pass, 3 existing skips, 0 fail**, 423 assertions across
58 tests in two files. The isolation change also passed package typecheck/build;
the readiness follow-up rechecked both test files and their helpers strictly.
CLI help runs inside the same isolated boundary.

Required monorepo checks were attempted in the task worktree. Name/dependency
checks pass; manifest validation stops because the sibling contracts CLI cannot
resolve `commander`. The affected build stops at Bridge's missing `commander` and
`zod` dependencies. The readiness worktree encountered the same dependency class
in Connectors/Servers, with the contracts validator still missing `commander`.
These worktree dependency limitations are not passing checks.
The full Recordings release gate was not rerun. No installation, publication,
live application launch, microphone/clipboard action, or host preference change
is part of this validation.

The supervisor environment again carries the fixture-only
`RECORDINGS_TEST_SMOKE_ALLOW_NON_DARWIN=1` opt-in. Its removal during confinement
work caused Linux fixtures to stop at the production platform guard before reaching
the copied tool adapter. The real `uname` selection and Darwin tool pinning are
unchanged. A focused regression executes the production guard as a pure decision:
Linux without the opt-in refuses, Linux with the supervisor environment passes,
and Darwin does not require the flag. Removing the restored variable makes this
regression fail on Darwin too. The decision regression plus a real confined Darwin
runtime-smoke acceptance case passed **2 tests, 24 assertions, 0 failures** (2.59s)
on Bun 1.3.14. The test file's strict TypeScript check passed. This preserves the
expected Linux seam; a real Linux runtime suite was not run in this follow-up.

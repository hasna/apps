# Confined installer and publication fixtures

This repairs the ten finalized-installer and four release-publication failures in
[the 0.4.0 baseline](0.4.0-validation.md). It is focused fixture evidence; it does
not establish a passing full release gate or validate an installed app.

The publication fixtures canonicalize their own private scratch roots before
calling the unchanged descriptor-relative publisher. macOS temporary-directory
aliases no longer prevent tests from reaching no-replace, recovery, alias binding,
and immutable-directory checks. A negative control supplies a symlinked ancestor
and verifies that the real native guard refuses before publishing or losing the
staged bytes. Existing destination-race and substitution assertions remain active.

The installer fixtures retain the actual Darwin kernel branch and all production
trust checks. Only copies inside the scratch root receive owned tool capabilities.
The copied resolver uses the real clean `env -i` launch path: fictional signing and
status responses live in the owned executables, not in an inherited environment
that production ignores. Its canonical path capability resolves real filesystem
paths, including symlinks; unsafe CLI symlinks and writable executables still fail.
Its temporary-directory capability confines the installer's hardcoded `/tmp`
workspace to the fixture root. The genuine descriptor-guard addon is copied to
its packaged Darwin location, without changing its bytes or adding an override.

Six shell crash-boundary cases had obsolete Darwin expectations. Release shell
installation now requires the root-owned updater broker before any transaction.
Each hook and retry must produce that refusal and preserve the prior app, with
no transaction, state directory, or tool invocation. These cases do **not** claim
to exercise broker recovery. The historical non-Darwin recovery assertions remain.
A separate control runs the unadapted Darwin script and verifies that inherited
fixture tool overrides cannot make it execute a host signing tool. Tailscale
status refusals also assert their specific failure and authenticated-snapshot
invocation, so an unrelated early preflight failure cannot satisfy the test.

## Single OS boundary

Use Bun 1.3.14. From the repository root:

```sh
(cd apps/recordings && /bin/bash scripts/build_native_fs_guard.sh)
python3 apps/recordings/src/__tests__/helpers/run-publication-fixtures.py \
  --bun /absolute/path/to/bun
```

The runner accepts only those two fixture groups. It creates private disposable
roots, starts one `sandbox-exec` boundary around the entire Bun process, and denies
network, Mach service lookup, outside writes, execution outside the fixed benign
allowlist and owned fixture root, and signals outside the sandbox cohort. Host
application, recorder state, preference, Keychain, and TCC reads are also denied.
This covers in-process native filesystem calls as well as child shell commands.
An alias inside the disposable root deliberately reproduces symlinked `TMPDIR`.

Before the suite, and again inside each test-runner process, actual OS probes
verify an allowed fixture write and self signal-zero, a denied sacrificial sibling
write, denied real `defaults help` execution, and denied signal-zero to the outside
supervisor. Signal zero cannot deliver a signal even if a broken profile allowed
it. No test runs if these checks fail. The helper does not trust a marker alone;
unconfined Darwin fixture invocation fails closed. Do not nest this runner inside
another sandbox, or include these groups in a surrounding sandbox without the
same verified root/probe contract. The five-minute deadline terminates only the
newly created fixture process group.

The full suite includes existing non-Darwin-only skips. No skip was added on
Darwin. No real installation, updater service, publication, application launch,
microphone, clipboard, preferences, Keychain, or TCC operation is exercised.

## Remaining production host compatibility issue

On this actual macOS host, `/usr/bin/realpath` is absent. The unchanged production
resolver calls it at `scripts/resolve_tailscale_cli.sh:148` while checking the
snapshot parent, and also at lines 99 and 273 for CLI/app paths. Consequently the
Tailscale-bound local install path (`scripts/install_macos_app.sh:486`) and the
required new local-only builder authentication path
(`src/native/Recordings/build.sh:1142`) cannot pass that check on this host.
Legacy hardware-UUID local installation avoids the resolver. Release shell
installation already refuses at the broker boundary, and release building does
not enter this local-only identity branch. The copied fixture's path capability
is **not** a production compatibility fix; that issue remains separate work.

## Validation evidence

The final single-boundary run with exact Bun 1.3.14 reports:

```text
42 pass
93 skip
0 fail
287 expect() calls
Ran 135 tests across 2 files. [85.26s]
```

The uncorrected confined baseline was 25 pass, 93 skip, 15 fail: the original
fourteen failures plus relative-HOME preflight blocked by real codesign denial.
The latter now reaches the canonical-HOME check through an owned fixture tool.
The two added cases are the publication symlink refusal and unadapted Darwin
installer control. Existing skips were unchanged.

`bun run typecheck`, strict checking of the new confinement helper, Python runner
parsing, and `git diff --check` pass. A stricter standalone TypeScript check of
both full fixture files also finds pre-existing diagnostics in `macos_artifact.ts`
and unchanged lifecycle tests; it is not a passing check. Those diagnostics were
reproduced against the unchanged HEAD versions of the same fixture files.
No broad gate, real installer, or actual updater recovery was run for this delta.

fix(recordings): make the prepublish gate pass in a normal local environment (HC-00677). `prepublishOnly` ran a plain `bun test` — the full suite under Bun's default 5000ms per-test timeout, with no partition check and no `RECORDINGS_TEST_TIMEOUT_MS` — so `npm publish` was blocked off-CI on timeout/environment failures the CI workflow already compensates for. It now runs `test:gated`, the same partition the Linux CI gate runs: the `ci-linux-suite` partition check first (the documented, non-silent quarantine mechanism), then the gated suite under `RECORDINGS_TEST_TIMEOUT_MS` (default 120000ms). This also fixes `test:gated`'s own timeout delivery: `RECORDINGS_TEST_TIMEOUT_MS="${...:-120000}" bun test --timeout "$RECORDINGS_TEST_TIMEOUT_MS"` expanded the bare `$RECORDINGS_TEST_TIMEOUT_MS` argument BEFORE the assignment prefix took effect (POSIX), so `--timeout` reached bun empty and the suite ran at Bun's 5000ms default — measured failing `database.test.ts > closeDatabase` at 5000ms (6035ms elapsed) on the first gated run. The argument now carries its own `:-120000` default and provably reaches bun as `--timeout 120000`. The macOS-only native fs-guard prebuild requirement is unchanged and remains enforced at pack time by `prepack:platform-gate`. Contract regression tests pin the gate shape.

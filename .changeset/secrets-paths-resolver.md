Switch @hasna/secrets local path reads/writes through the @hasna/paths resolver (XDG/macOS home layout). The operator vault data dir (vault.db, key material, aws.json, aws-sync-state.json) now resolves through `dataDir({app:"secrets"})` with gated legacy adoption: the legacy `~/.hasna/secrets` home stays the effective default until the store has actually been migrated to the XDG data home (`~/.local/share/hasna/secrets` on Linux, `~/Library/Application Support/Hasna/secrets` on macOS) or the operator sets the data-kind override `HASNA_DATA_HOME` — an existing local vault never becomes invisible on upgrade. The `~/.secrets` env-file bridge (import-env/export-env) is a separate legacy credential store and is deliberately unchanged. Install-time dir creation (postinstall) follows the same resolution. Dependency pinned exactly to `@hasna/paths@0.1.0` — the wave-wide pin for the hasna/apps resolver-switch lanes (XDG home migration, hotfixes plan 0f49f56a, task P3.3).

Resolver validation fixes, round 2 (hasna/apps#1720): the `contacts-mcp` startup gate now refuses every deliberate credential tier it cannot honour — the secrets-vault pointer `HASNA_CONTACTS_API_KEY_REF` is dereferenced once at startup (the chain alone only validated its shape, so a pointer the vault could not complete started the server and answered `initialize`), and a missing `HASNA_PROFILE` credentials file, an unsafe (not owner-only) credentials file, or a Keychain item that cannot be read is a one-line refusal on the first stderr line, never a `Fatal error` stack trace. With no credential resolvable through the @hasna/contracts chain the server still exits non-zero BEFORE the stdio transport is connected or the HTTP port is bound, never answers `initialize`, and creates nothing under the app home; the first stderr line names where the credential should live (`CONTACTS_API_NOT_CONFIGURED`, the Keychain item, the credentials-file path, `HASNA_CONTACTS_API_KEY`), never a value. `--help` / `--version` still answer ahead of the gate and every tool re-resolves per call. README documents the gate and that `./sdk` `createContactsClient()` resolves the literal tiers only (the vault pointer is refused with `CONTACTS_CREDENTIAL_POINTER_UNSUPPORTED`).

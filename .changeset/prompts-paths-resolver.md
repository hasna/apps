Switch @hasna/prompts local path reads/writes through the @hasna/paths resolver (XDG/macOS home layout, hotfixes plan 0f49f56a task P3.3). The primary SQLite store (`~/.hasna/prompts/prompts.db`), the dispatch run-records directory (`~/.hasna/prompts/runs`), and the `prompts runbook lint` default prompt directory now resolve from the effective data root: an exact-app override (`HASNA_PROMPTS_HOME`, then the pre-existing `PROMPTS_HOME`) wins unconditionally; otherwise the resolver data home (`~/.local/share/hasna/prompts` on Linux, `~/Library/Application Support/Hasna/prompts` on macOS) is adopted only when the operator sets the data-kind override `HASNA_DATA_HOME` or the store has already been physically migrated there (`prompts.db` present) — the legacy `~/.hasna/prompts` root stays the effective data home until then, so an existing live store never becomes invisible on upgrade. The legacy `~/.prompts/` one-time merge now targets the effective root, and the install-time postinstall provisions the same effective data root instead of hardcoding `$HOME/.hasna/prompts`. The runbook default keeps the legacy `~/.hasna/loops/prompts` convention until adoption, then points at the adopted root's `runbook` subdir. The dependency is pinned exactly to `@hasna/paths@0.1.0` — the wave-wide pin for the hasna/apps resolver-switch lanes. Nothing moves on disk in this phase.

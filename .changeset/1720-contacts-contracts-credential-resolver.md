Adopt the @hasna/contracts 1.0.2 credential resolver (owner directive, hasna/apps#1720): CLI, MCP server and store resolve the contacts API key and authority through the shared client chain on every request — explicit argument, deliberate pointers (`HASNA_CONTACTS_API_KEY_OVERRIDE`, `HASNA_PROFILE`, `HASNA_CONTACTS_API_KEY_REF`), macOS Keychain (`hasna.credentials.contacts.api-key` / `.api-url`, account `HASNA_STATION` → short hostname → `$USER`), `~/.hasna/contacts/config/credentials` (0400/0600), then `HASNA_CONTACTS_API_KEY` — with the authority defaulting to the fleet gateway `https://api.hasna.com/contacts` once any credential resolves. No credential fails closed: non-zero exit, no SQLite, no local-fallback event, and the Keychain tier stays ambient across per-request env snapshots (#1788). The SDK keeps an explicit HTTPS `baseUrl` + `apiKey` contract and never attaches an ambient fleet key to an explicit authority (#1794). Legacy client selectors (`HASNA_CONTACTS_STORAGE_MODE`, `CONTACTS_STORAGE_MODE`, DB paths/URLs) are rejected in client processes; the own env/disk chain is gone, and the vendored storage kit is regenerated for 1.0.2.

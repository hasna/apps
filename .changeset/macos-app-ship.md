Make the recordings macOS native build and ship path work on a real Mac. The Swift/C compile gate moved from the nested `apps/recordings/.github/workflows/ci.yml` (a silent dead lane — GitHub Actions only discovers workflows at the repo root, so the native half compiled nowhere in the monorepo) to the root-discoverable `.github/workflows/recordings-macos.yml`, scoped to `apps/recordings/**`. The resolver used by `build.sh local` and the installer now resolves `realpath` from both `/usr/bin/realpath` and `/bin/realpath` (macOS 26 ships it at `/bin` only — measured on station03/06/07), accepts a snapshot parent reached through a system symlink ancestor like macOS `/tmp -> /private/tmp` while still requiring the final component to be a real user-owned 0700 non-symlink directory, and passes the codesign requirement with the `-R=<expr>` form that macOS 26 documents (the space-separated form is treated as a file path and fails). A merged main now provably compiles the macOS app's Swift half and a local-only build can actually run on a fleet Mac, closing the "CI build-and-sign path" and "nothing builds or ships the macOS app to the owner's Mac" gaps named by the stale-sweep on todos 1a2ba6ad.

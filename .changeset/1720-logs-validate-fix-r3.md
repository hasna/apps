`logs-mcp --http` never binds without authority (hasna/apps#1720 validation, round 3 — station03 release verification). 0.5.0 bound `127.0.0.1:<port>` with no resolvable credential (`[logs-mcp] Streamable HTTP listening`), stayed alive and refused every session per request (-32603). The Streamable-HTTP listener factory (`startMcpHttpServer`) now runs the store's authority preflight itself — `assertStoreConfigured`: fail-closed store selection plus the one-time vault-pointer completion, the same preflight the `logs-mcp` startup gate runs — right before the harness creates the socket, so a process with no credential, or a deliberate tier it cannot honour, exits non-zero with the remedy as its first stderr line BEFORE any port is bound, whichever entry reaches the factory (the bin, an embedder, a CLI verb). The explicit `HASNA_LOGS_LOCAL=1` opt-in still serves over HTTP with its single local-mode notice. Hermetic spawned tests pin `--http --port 0` (non-zero exit, no listener line, nothing created), a reserved port refused on every probe until exit with `initialize` never answered over HTTP, a deliberate profile refused before the bind, `--version` answered before any bind or tier, and the local opt-in over HTTP; in-process tests pin the factory's own refusal.

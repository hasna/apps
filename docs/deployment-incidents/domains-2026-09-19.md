# Domains deployment reconciliation — September 19, 2026

## Scope

Production deployment run `35427160220` attempted to deploy the reviewed Domains
candidate built from source `f624fbffde3aa304ebed20bca58af182b52a7704`.
The image passed the local zero-CRITICAL/HIGH vulnerability gate. The migration
task completed successfully and advanced the ledger by `domains_0033`,
`domains_0034`, and `domains_0035`.

## Failure

The service candidate was registered from the currently running task revision,
which predated hosted provider-secret injection. The new containers therefore
failed closed with:

```text
CLOUDFLARE_API_TOKEN is required for hosted provisioning
```

The ECS circuit breaker retained the already-running stable tasks. The
corrective deployment workflow emitted `RECONCILIATION_REQUIRED` and did not
perform an automatic application rollback after schema advancement.

## Reconciliation

Before changing the service pointer, the operator proved all of the following:

- the failed primary deployment was the exact candidate from run `35427160220`;
- the only completed deployment was the prior revision already serving both
  desired tasks;
- the canonical readiness endpoint returned HTTP 200;
- readiness reported zero pending migrations;
- the running version continued to serve the advanced additive schema.

The service pointer was then reconciled to that already-running stable revision.
No replacement task was launched by the reconciliation. Readback showed one
completed primary deployment, two desired/running tasks, and zero pending tasks.

## Successor guard

Follow-up `hasna/apps#2497` projects the reviewed `web_secrets` manifest into
every candidate service task while preserving its existing database and signing
secrets. It also refuses a failed deployment pointer as a future rollback anchor.
A successor deployment must pass canonical authenticated gateway acceptance
before this incident is considered closed.
